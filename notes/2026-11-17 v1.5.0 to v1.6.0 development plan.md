## 1. Executive Summary

An audit of 436 log files from ECOSTRESS Collection 3 DAG run `EcostressDAG_Col3.46163.0802.20261116T031326109` identified **2,071 errors** and **15,908 warnings** across 140 unique issue types. Cross-referencing those findings against the `VCD43NRT v1.5.0` source tree reveals:

1. **Already Mitigated in `v1.5.0`:** The shared-filesystem race conditions within `VCD43NRT` granule and layer generation (**Root Cause #2**, accounting for **316 errors** and **1,164 warnings**) have already been substantially addressed in `v1.5.0` via PID/UUID-scoped temporary GeoTIFF writes (`_atomic_write_geotiff`), PID/UUID-scoped granule staging directories (`.tmp`), and atomic `h5py`-validated VIIRS HDF5 downloads. (The failed DAG run executed against a container image built prior to `v1.5.0`.)
2. **Remaining Actionable Issues for `v1.6.0`:**
   - **NASA CMR Transient HTTP 500 Errors (Root Cause #5):** `VIIRS_CMR_query()` lacks retry/backoff logic and immediately raises `CMRServerUnreachable` on transient 5xx responses.
   - **Promotion-Window Race Condition in `VCD43NRT.VCD43NRT()`:** Between `shutil.rmtree(directory)` and `os.replace(temp_directory, directory)`, two concurrent workers finishing simultaneously can still collide or delete an incomplete/peer directory without a filesystem lock.
   - **Unprotected Staged Raster Reads in `BRDF_parameters()` / `_read_brdf_stack()`:** Unlike `VIIRSGranule`, `VCD43NRT` staging reads do not catch corrupt/truncated GeoTIFFs on disk and self-heal.
   - **Redundant Work Under High Concurrency:** Without per-granule/per-band locking, overlapping MGRS tiles (e.g., 10 tiles overlapping `h13v14`) still run duplicate 16-day BRDF inversions in parallel before discarding duplicate outputs at promotion time.
3. **External Repository Dependencies (Out-of-Repo Fixes Required):**
   - **`GEOS5FP` (`>=2.23.0`):** Missing `gdal_HDF5.so` validation failure and non-atomic shared `.nc4` downloads (**Root Cause #1**, 1,281 errors).
   - **`modland` (`>=1.1.2`):** `tuple * Affine` `TypeError` on tile `56UNA` (**Root Cause #4**, 32 errors).
   - **`ECOv003_L2T_STARS`:** `LandFilter` logged at `ERROR` severity for 148 ocean tiles (**Operational Filter**, 334 errors).

## 3. Detailed Codebase Diagnostic (`VCD43NRT v1.5.0`)

### 3.1 What `v1.5.0` Fixed (and Why the Logs Still Showed Failures)
Inspection of `VCD43NRT v1.5.0` confirms that the following concurrency safeguards are already merged into `main`:
- **`VCD43NRT/VIIRS_granule.py` (`_atomic_write_geotiff`, lines 32–45):** Generates a unique temporary filename per process and invocation (`f"{filename}.{os.getpid()}.{uuid.uuid4().hex}.tmp.tif"`), writes the GeoTIFF or COG, and atomically moves it into place via `os.replace(temp_filename, filename)`.
- **`VCD43NRT/VCD43NRT.py` (`VCD43NRT.VCD43NRT`, lines 505–612):** Creates an isolated temporary directory `.{granule_ID}.{pid}.{uuid}.tmp/{granule_ID}`, writes all I-band, NDVI, M-band, and broadband albedo layers there, checks `staging_granule.complete`, and atomically promotes the completed directory.
- **`VCD43NRT/VIIRS.py` (`download_granules`, lines 237–300):** Downloads granules into a unique `tempfile.mkdtemp()` folder, validates HDF5 readability via `h5py.File`, and moves valid files into the shared cache with `os.replace()`.

**Root Cause of Log Discrepancy:** In the failed run (`20261116T031326109`), logs emitted `removing stale VCD43NRT granule output directory before regeneration` and `...NBAR_I1.temp.tif`. Those log strings no longer exist in `v1.5.0`, confirming the HPC/cloud worker container was still running an older build (`<= v1.4.0`).

### 3.2 Remaining Defects & Concurrency Edge Cases in `v1.5.0`

#### Issue A: Un-retried NASA CMR Queries (`VCD43NRT/VIIRS_query.py`, lines 66–69)
```python
try:
    granules = query.get()
except Exception as e:
    raise CMRServerUnreachable(e)
```
- **Diagnostic:** NASA's Common Metadata Repository (`cmr.earthdata.nasa.gov`) periodically returns HTTP `500 Internal Server Error` or `503 Service Unavailable` under bursty parallel queries (observed on tile `18FXG`, Issue `#95`). Because `VIIRS_CMR_query` performs zero retries, a single transient blip fails the entire tile job.
- **Required Fix:** Retry `query.get()` up to `RETRIES` times with exponential backoff + jitter (e.g., `2s, 4s, 8s...`) before raising `CMRServerUnreachable`.

#### Issue B: Non-Atomic Directory Promotion Race (`VCD43NRT/VCD43NRT.py`, lines 596–607)
```python
if granule.complete:
    logger.info(f"peer worker completed VCD43NRT granule concurrently: {directory}")
    return granule

if exists(directory):
    logger.warning(f"removing incomplete VCD43NRT granule output directory before promotion: {directory}")
    shutil.rmtree(directory, ignore_errors=True)

try:
    os.replace(temp_directory, directory)
except OSError:
    if granule.complete:
        return granule
    raise
```
- **Diagnostic:** There is a TOCTOU (Time-of-Check to Time-of-Use) window between `if granule.complete:`, `shutil.rmtree(directory)`, and `os.replace(temp_directory, directory)`. If Worker A checks `granule.complete` (`False`), Worker B promotes `directory` (`True`), and Worker A then executes `shutil.rmtree(directory)` before its own `os.replace()`, Worker A will delete Worker B's valid completed directory (or partially delete files inside it while a downstream reader opens them).
- **Required Fix:** Guard the promotion critical section with a `SoftFileLock` (`f"{directory}.lock"`), re-checking `granule.complete` *after* acquiring the lock.

#### Issue C: Duplicate Compute Across Overlapping MGRS Tiles (`VCD43NRT/VCD43NRT.py`, lines 495–612)
- **Diagnostic:** Up to 10 MGRS tiles map to a single MODIS sinusoidal tile (e.g., `h13v14`). In `v1.5.0`, all 10 concurrent workers see `granule.complete == False` at startup, and all 10 independently download 16 days of VIIRS data, stage rasters, and run the Rust BRDF solver for the exact same sinusoidal tile before 9 of them discard their work at promotion.
- **Required Fix:** Acquire a per-granule `SoftFileLock` (or per-band staging lock) so one worker computes the sinusoidal tile while peer workers wait and immediately reuse the completed granule (`if granule.complete: return granule`).

#### Issue D: No Corrupt-File Recovery in `VCD43NRT_staging` (`VCD43NRT/VCD43NRT.py`, lines 155–171 & 358–421)
- **Diagnostic:** `BRDF_parameters()` checks `if exists(reflectance_filename):` and skips regeneration without verifying that the GeoTIFF is readable. Similarly, `_read_brdf_stack()` calls `Raster.open(filename)` without catching GDAL/Rasterio read errors. If a pre-`v1.5.0` run or abrupt node preemption left a 0-byte or truncated `.tif` in `VCD43NRT_staging/`, every subsequent retry will crash on that file until manually purged.
- **Required Fix:** Validate staged rasters when reading (or catch read errors in `_read_brdf_stack()` / `BRDF_parameters()`, delete the corrupt file, and regenerate it).

#### Issue E: Immediate Tight-Loop Retries in `VIIRS.download_granules` (`VCD43NRT/VIIRS.py`, lines 248–296)
- **Diagnostic:** `download_granules()` retries up to `RETRIES` (6) times with zero sleep/backoff between iterations. When Earthdata/LPCLOUD returns transient 503s or rate-limits parallel workers, immediate retries hammer the endpoint and exhaust all 6 attempts within seconds.
- **Required Fix:** Add exponential backoff with jitter (`time.sleep(min(30, 2 ** attempt + random.uniform(0, 1)))`) between retry attempts.

## 4. `VCD43NRT v1.6.0` Development Plan

### Milestone 1: Resilient Remote Queries & Downloads
- [ ] **Task 1.1 (`VCD43NRT/VIIRS_query.py`):** Add configurable retry-with-exponential-backoff around `query.get()` in `VIIRS_CMR_query()` (default `max_retries=4`, base delay `2.0s`, jitter). Ensure non-transient errors (e.g., invalid mission/geometry) are not masked, while network/HTTP 5xx exceptions retry cleanly before raising `CMRServerUnreachable`.
- [ ] **Task 1.2 (`VCD43NRT/VIIRS.py`):** Add exponential backoff with jitter between retry iterations in `VIIRS.download_granules()`.

### Milestone 2: Lock-Guarded Granule Promotion & Deduplicated Execution
- [ ] **Task 2.1 (`pyproject.toml`):** Add `filelock>=3.13.0` to `[project.dependencies]`. (Use `filelock.SoftFileLock` rather than `UnixFileLock`/`flock` for compatibility with NFS/Lustre/GPFS shared filesystems on HPC clusters.)
- [ ] **Task 2.2 (`VCD43NRT/VCD43NRT.py`):** Wrap granule generation/promotion in `VCD43NRT.VCD43NRT()` with a per-granule `SoftFileLock` (`f"{directory}.lock"`, configurable timeout, e.g., `timeout=1800`):
  1. Fast-path check `if granule.complete: return granule` before acquiring lock.
  2. Acquire `SoftFileLock(f"{directory}.lock")`.
  3. Re-check `if granule.complete: return granule` immediately upon acquiring lock (so peer workers that waited on the lock return the newly completed granule in milliseconds).
  4. Execute staged generation in `.tmp`, safely remove any incomplete `directory`, and promote via `os.replace(temp_directory, directory)`.

### Milestone 3: Self-Healing Staging Cache
- [ ] **Task 3.1 (`VCD43NRT/VCD43NRT.py`):** Update `BRDF_parameters()` and `_read_brdf_stack()` so that if an existing file in `VCD43NRT_staging/` fails `Raster.open()` or fails shape/NaN sanity checks, it is logged as a warning, unlinked (`os.remove`), and regenerated from the source VIIRS granule rather than crashing the run.

### Milestone 4: Test Coverage & Release Engineering
- [ ] **Task 4.1 (`tests/test_viirs_query.py`):** Add unit tests verifying that `VIIRS_CMR_query()` retries transient `RuntimeError`/HTTP 500 exceptions and succeeds on subsequent attempts, and raises `CMRServerUnreachable` after exhausting retries.
- [ ] **Task 4.2 (`tests/test_concurrency_and_downloads.py`):** Add tests for:
  - Concurrent `VCD43NRT()` calls on the same `(date_UTC, tile)` verifying that `SoftFileLock` prevents `shutil.rmtree` from clobbering a peer worker's completed directory and prevents duplicate BRDF computation.
  - Corrupt staged `.tif` recovery in `BRDF_parameters()`.
- [ ] **Task 4.3 (`pyproject.toml` & Deployment):** Bump version to `1.6.0`, verify CI wheels across Python 3.11–3.14, and rebuild the ECOSTRESS Collection 3 runtime container image (ensuring `VCD43NRT>=1.6.0`, updated `GEOS5FP`, `modland`, and `libgdal-hdf5` are installed).
